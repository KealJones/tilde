~ Tilde vs the other browser runtimes

One 4-bit model (LFM3 1.7B or Qwen3 0.6B) on every runtime that has a build of it. Each test runs alone in a fresh page load and writes every step to this browser's storage as it goes, so a tab iOS kills still leaves its result: the next load records how far it got and moves on to the next test. Results never leave this phone unless you export or share them.

New run

The first pass downloads each runtime's own copy of the model (LFM3: about 5.6 GB in all, Qwen3 0.6B: about 2 GB; keep the phone on Wi-Fi, awake and on this tab). Tests take turns by prompt size, so the phone warms up evenly for everyone. A runtime that dies or times out on a prompt isn't asked to try a longer one.

What each column means

Load: from asking the runtime to load to ready, with the model already downloaded. Read: prompt tokens per second while reading the prompt. Write: tokens per second while writing, after the first. First token: from sending the prompt to the first written token. GPU: peak WebGPU buffer memory made on this page and not yet destroyed, counted the same way for every runtime by watching createBuffer; wllama runs in a worker, so its memory isn't visible here. Worst frame: the longest the page went without drawing while writing (a stalled screen). Every runtime gets the same text, greedy decoding, no repeat penalty, and one short warm-up request first. LiteRT-LM only takes chat messages, so its prompt also gets the chat template's few tokens.
